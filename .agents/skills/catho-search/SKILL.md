# Catho Search Skill

Search live job listings from Catho (catho.com.br), Brazil's largest general job board.
No authentication, no API key, and **zero runtime dependencies** — it runs with just `bun`.

> This is a market-specific skill generated by `/add-portal` for the Brazil job market
> (Portuguese-language postings). Per repo policy, market-specific portal skills like this
> one live in the user's fork rather than being merged upstream.

## Personal use note

`robots.txt` explicitly allows the search/detail paths this skill uses (only a handful of
unrelated paths and query-string forms are disallowed — see `url-reference.md`), and lists
several AI/search crawlers, including Claude-Web and anthropic-ai, as allowed. A dedicated
Terms-of-Use page could not be located to double-check bulk-access rules. As a precaution,
**treat this as personal use**: keep request volume low, don't use it commercially or for
bulk data collection.

## When to use this skill

- Search for job openings in Brazil by keyword, job title, or technology
- Narrow results to a specific Brazilian city or state
- Get the full description of a specific Catho job listing
- Filter results by how recently they were posted (client-side — see Notes)

## Commands

### Search job listings

```bash
bun run .agents/skills/catho-search/cli/src/cli.ts search --query "<title>" [flags]
```

Key flags:
- `--query <text>` / `-q <text>` — **required.** Job title or keyword, e.g. `"desenvolvedor flutter"`.
- `--location <text>` / `-l <text>` — optional. A Brazilian city (`"Curitiba"`) or state abbreviation (`"PR"`).
- `--jobage <days>` — only postings dated within N days. Client-side filter (Catho has no server-side date parameter — see Notes). Omit for all postings.
- `--page <n>` — page number (1-indexed).
- `--limit <n>` / `-n <n>` — cap total results emitted (client-side).
- `--format json|table|plain` — default `json`.

### Fetch full job detail

```bash
bun run .agents/skills/catho-search/cli/src/cli.ts detail <id|url> [--format json|plain]
```

`id` is the job ID from `search` results (e.g. `37584918`). You may also pass a full Catho
`/vagas/.../<id>` URL — only the trailing numeric id matters, Catho resolves the posting
from it regardless of the slug text. Returns the full description, employment type, and
posted date from the posting's own `schema.org/JobPosting` structured data.

## Usage examples

```bash
# Flutter developer roles anywhere in Brazil
bun run .agents/skills/catho-search/cli/src/cli.ts search -q "desenvolvedor flutter" --format table

# Flutter developer roles in Curitiba specifically
bun run .agents/skills/catho-search/cli/src/cli.ts search -q "desenvolvedor flutter" -l "Curitiba" --format table

# Mobile developer roles in Paraná state, posted in the last 7 days
bun run .agents/skills/catho-search/cli/src/cli.ts search -q "desenvolvedor mobile" -l "PR" --jobage 7 --format table

# Broader "desenvolvedor" search, page 2
bun run .agents/skills/catho-search/cli/src/cli.ts search -q "desenvolvedor" --page 2 --format json

# Full details for a specific job
bun run .agents/skills/catho-search/cli/src/cli.ts detail 37584918 --format plain
```

## Output formats

| Format | Best for |
|--------|----------|
| `json` | Default — programmatic use, passing IDs to `detail` |
| `table` | Quick human-readable scanning |
| `plain` | Reading a single job's full detail (`detail` command) |

All errors are written to **stderr** as `{ "error": "...", "code": "..." }` and the process exits with code `1`.

## Notes

- Data is scraped from Catho's public, server-rendered search-results HTML; job detail is
  read from the posting's own `schema.org/JobPosting` JSON-LD block, which is more reliable
  than scraping the rendered detail page.
- **No confirmed server-side date/recency parameter.** `--jobage` is implemented as a
  client-side filter over each result's own posted-date text, converted to an ISO date. This
  means `--jobage` only filters *within whatever page you fetched* — it does not fetch
  additional pages to backfill a smaller-than-requested result set.
- Location filtering is a path segment (`/vagas/<query>/<location>/`), not a query
  parameter — pass city or state names in `--location` and the CLI builds the URL.
- Catho may rate-limit; the CLI retries 429/5xx with exponential backoff. Keep volume low
  (see the personal-use note above).
- Job IDs are numeric (e.g. `37584918`) — pass them as-is to `detail`.
