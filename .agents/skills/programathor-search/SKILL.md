# ProgramaThor Search Skill

Search live job listings from ProgramaThor (programathor.com.br), a developer-focused
Brazilian job board. No authentication, no API key, and **zero runtime dependencies** —
it runs with just `bun`.

> This is a market-specific skill generated by `/add-portal` for the Brazil job market
> (Portuguese-language postings). Per repo policy, market-specific portal skills like this
> one live in the user's fork rather than being merged upstream.

## Search-only — no detail command

Every job detail page (`/jobs/<id>-<slug>`) returns a genuine **site-side HTTP 500**,
confirmed live across multiple job ids, a browser-like User-Agent, and a
trailing-slash/`.json` URL variant — this is ProgramaThor's own bug at the time this
skill was built, not a bot-detection response or a parsing gap in this CLI. Running
`detail` returns a clear, documented `DETAIL_UNSUPPORTED` error rather than silently
failing or returning garbage. Use `search`'s own output (title, company, location,
tech-stack tags) — it already carries most of what a detail fetch would add, short of
the full job description.

## No server-side search — `--query` is a client-side filter

ProgramaThor's own site has no full-text search parameter: `q=`, `search=`, `query=`, and
`keyword=` were all probed live and confirmed to be silently ignored no-ops (byte-for-byte
identical result sets aside from a per-request CSRF token). `--query` is instead matched
client-side, by word, against each fetched card's title and tech-stack tags — see Notes.

## Personal use note

`robots.txt`'s generic `User-agent: *` rule allows the paths this skill uses (only
`/admin/`, `/user/`, `/users/`, `/company/` are disallowed — none of which `search`
touches). No dedicated Terms-of-Use restrictions on automated access were found. Keep
request volume low regardless, as a general courtesy.

## When to use this skill

- Search for developer/programmer job openings in Brazil by technology or role keyword
- Narrow results to a specific Brazilian city, or to remote-only listings
- See each listing's tech-stack tags at a glance (a field most portals in this repo don't expose)

## Commands

### Search job listings

```bash
bun run .agents/skills/programathor-search/cli/src/cli.ts search --query "<keyword>" [flags]
```

Key flags:
- `--query <text>` / `-q <text>` — **required.** Split into words and matched (AND, case-insensitive) against each card's title and tech-stack tags, e.g. `"flutter"` or `"desenvolvedor flutter"`.
- `--location <text>` / `-l <text>` — optional. A Brazilian city (`"Curitiba"`) or the literal `"Remoto"` — maps to ProgramaThor's own `place` filter, confirmed live to genuinely narrow results.
- `--page <n>` — page number (1-indexed). `--query` filters only within the one page fetched (15 cards) — it does not auto-fetch further pages to backfill a small result set.
- `--limit <n>` / `-n <n>` — cap total results emitted (client-side).
- `--format json|table|plain` — default `json`.

### Fetch full job detail

**Not supported.** `detail <id>` always exits 1 with a `DETAIL_UNSUPPORTED` error — see above.

## Usage examples

```bash
# Flutter roles (client-side filtered from the current /jobs listing)
bun run .agents/skills/programathor-search/cli/src/cli.ts search -q "flutter" --format table

# Same, narrowed to Curitiba
bun run .agents/skills/programathor-search/cli/src/cli.ts search -q "flutter" -l "Curitiba" --format table

# Remote React roles, page 2 of the listing
bun run .agents/skills/programathor-search/cli/src/cli.ts search -q "react" -l "Remoto" --page 2 --format table

# Multi-word query — matches by word, not as one contiguous phrase
bun run .agents/skills/programathor-search/cli/src/cli.ts search -q "desenvolvedor flutter" --format json
```

## Output formats

| Format | Best for |
|--------|----------|
| `json` | Default — programmatic use |
| `table` | Quick human-readable scanning |
| `plain` | Reading results one at a time, including their tech-stack tags |

All errors are written to **stderr** as `{ "error": "...", "code": "..." }` and the process exits with code `1`.

## Notes

- Every result includes a bonus `tags` array (e.g. `["Flutter", "Dart", "Firebase"]`) — the
  site's own tech-stack pills for that listing. No other portal skill in this repo exposes
  this, and it's what makes the client-side query filter meaningfully more precise than
  matching on title text alone.
- `date` is always `null` — ProgramaThor's listing cards carry no posting-date field of
  any kind (not even a relative "há 3 dias" string), so there is nothing to report and
  nothing to filter by age. `--jobage` is not a recognized flag; passing it is rejected
  with `UNKNOWN_FLAG` rather than silently accepted and ignored.
- ProgramaThor may rate-limit; the CLI retries 429/5xx with exponential backoff. Keep
  volume low regardless.
- Job IDs are numeric (e.g. `33724`) and appear as the leading digits of the slug in
  `/jobs/<id>-<slug>` URLs.
- If ProgramaThor fixes the detail-page 500 in the future, re-run `/add-portal` on
  `programathor.com.br` to add a working `detail` command — the underlying markup is
  otherwise straightforward to parse (see `url-reference.md`).
