# Vagas.com Search Skill

Search live job listings from Vagas.com (vagas.com.br), one of Brazil's largest general
job boards. No authentication, no API key, and **zero runtime dependencies** — it runs
with just `bun`.

> This is a market-specific skill generated by `/add-portal` for the Brazil job market
> (Portuguese-language postings). Per repo policy, market-specific portal skills like this
> one live in the user's fork rather than being merged upstream.

## Personal use note

`robots.txt`'s generic `User-Agent: *` rule allows the search (`/vagas-de-<slug>`) and
detail (`/vagas/v<id>/...`) paths this skill uses — only a handful of unrelated paths
(`/auth/`, `/servicos/`, `/api/`, `/vagas/pesquisas`, etc. — see `url-reference.md`) are
disallowed. A dedicated Terms-of-Use page could not be located to double-check
bulk-access rules. As a precaution, **treat this as personal use**: keep request volume
low, don't use it commercially or for bulk data collection.

## When to use this skill

- Search for job openings in Brazil by keyword, job title, or technology
- Narrow results to a specific Brazilian city or state
- Get the full description of a specific Vagas.com job listing
- Filter results by how recently they were posted (client-side — see Notes)

## Commands

### Search job listings

```bash
bun run .agents/skills/vagas-search/cli/src/cli.ts search --query "<title>" [flags]
```

Key flags:
- `--query <text>` / `-q <text>` — **required.** Job title or keyword, e.g. `"desenvolvedor flutter"`.
- `--location <text>` / `-l <text>` — optional. A Brazilian city (`"Curitiba"`) or state name (`"São Paulo"`) — passed through to Vagas.com's own location facet.
- `--jobage <days>` — only postings dated within N days. Client-side filter (Vagas.com has no server-side date parameter — see Notes). Omit for all postings.
- `--page <n>` — page number (1-indexed).
- `--limit <n>` / `-n <n>` — cap total results emitted (client-side).
- `--format json|table|plain` — default `json`.

### Fetch full job detail

```bash
bun run .agents/skills/vagas-search/cli/src/cli.ts detail <id|url> [--format json|plain]
```

`id` is the job ID from `search` results (e.g. `2824782`). You may also pass a full
Vagas.com `/vagas/v<id>/<slug>` URL — only the numeric id matters, the slug segment is
cosmetic (a wrong-but-plausible slug 301-redirects to the canonical one).

## Usage examples

```bash
# Flutter developer roles anywhere in Brazil
bun run .agents/skills/vagas-search/cli/src/cli.ts search -q "desenvolvedor flutter" --format table

# Analyst roles in São Paulo specifically
bun run .agents/skills/vagas-search/cli/src/cli.ts search -q "analista" -l "São Paulo" --format table

# Mobile developer roles, posted in the last 7 days
bun run .agents/skills/vagas-search/cli/src/cli.ts search -q "desenvolvedor mobile" --jobage 7 --format table

# Broader "analista" search, page 2
bun run .agents/skills/vagas-search/cli/src/cli.ts search -q "analista" --page 2 --format json

# Full details for a specific job
bun run .agents/skills/vagas-search/cli/src/cli.ts detail 2824782 --format plain
```

## Output formats

| Format | Best for |
|--------|----------|
| `json` | Default — programmatic use, passing IDs to `detail` |
| `table` | Quick human-readable scanning |
| `plain` | Reading a single job's full detail (`detail` command) |

All errors are written to **stderr** as `{ "error": "...", "code": "..." }` and the process exits with code `1`.

## Notes

- Data is scraped from Vagas.com's public, server-rendered search-results HTML; job
  detail is also scraped from the rendered detail page — unlike some other portals in
  this repo, Vagas.com's detail pages carry no `schema.org/JobPosting` JSON-LD (confirmed
  live: only a generic `WebSite` schema block is present), so there is no structured-data
  shortcut here.
- **No confirmed server-side date/recency parameter.** `--jobage` is implemented as a
  client-side filter over each result's own `DD/MM/YYYY` posted-date text, converted to
  an ISO date. This means `--jobage` only filters *within whatever page you fetched* — it
  does not fetch additional pages to backfill a smaller-than-requested result set. A
  `?ordenar_por=mais_recentes` sort parameter exists on the site but is a sort, not a
  filter, so this CLI does not use it.
- Location filtering is the `e[]` query parameter (confirmed live: it genuinely narrows
  results, it is not a cosmetic no-op) — pass a city or state name in `--location` and
  the CLI builds the URL.
- Vagas.com may rate-limit; the CLI retries 429/5xx with exponential backoff. Keep volume
  low (see the personal-use note above).
- Job IDs are numeric (e.g. `2824782`) — pass them as-is to `detail`.
- Result volume for a narrow query can be genuinely tiny — `"desenvolvedor flutter"`
  returned exactly 1 live listing at the time this skill was built. That is real data,
  not a parsing failure; broaden the query (e.g. `"desenvolvedor mobile"`) for more hits.
