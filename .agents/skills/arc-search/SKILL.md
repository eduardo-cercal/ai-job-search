# Arc.dev Search Skill

Search live remote-job listings from Arc.dev, a global remote-tech job platform. No
authentication, no API key, and **zero runtime dependencies** — it runs with just `bun`.

> This is a global (not country-specific) skill generated by `/add-portal`. Unlike the
> Brazil-market skills in this repo, Arc.dev is remote-only and worldwide, so it complements
> local-market portal skills rather than replacing them.

## Access note

`robots.txt` is wide open (`Allow: /` for all bots, with an explicit `ClaudeBot` entry
carrying just a 10-second crawl delay, no disallow). Keep request volume low regardless,
and respect that crawl delay, matching the caution every portal skill in this repo carries.

## When to use this skill

- Search for remote software/engineering jobs by technology or skill tag
- Get the full description of a specific Arc.dev job listing (works for aggregated
  listings; Arc's own native listings may not expose full detail without an account — see Notes)
- Filter results by how recently they were posted (client-side — see Notes)

## Commands

### Search job listings

```bash
bun run .agents/skills/arc-search/cli/src/cli.ts search --query "<tag>" [flags]
```

Key flags:
- `--query <text>` / `-q <text>` — **required.** A technology/skill **tag**, not a free-text job title (Arc's search is category-based — see Notes). e.g. `"flutter"`, `"react"`, `"python"`, `"kotlin"`.
- `--jobage <days>` — only postings dated within N days. Client-side filter (Arc has no server-side date parameter — see Notes). Omit for all postings.
- `--page <n>` — accepted for interface consistency, but only page 1 returns results (see Notes).
- `--limit <n>` / `-n <n>` — cap total results emitted (client-side).
- `--format json|table|plain` — default `json`. Table view adds a `[arc]`/`[external]` source tag per row.

### Fetch full job detail

```bash
bun run .agents/skills/arc-search/cli/src/cli.ts detail <id|url> [--format json|plain]
```

`id` is the job ID from `search` results (e.g. `ph3excboow`). You may also pass a full
Arc.dev job URL — only the trailing id matters, Arc resolves and redirects to the correct
posting from it regardless of the slug text. Works reliably for aggregated ("external")
listings; an Arc-native ("arc") listing's detail page is not viewable this way (see Notes).

## Usage examples

```bash
# Remote Flutter roles worldwide
bun run .agents/skills/arc-search/cli/src/cli.ts search -q "flutter" --format table

# Remote React roles posted in the last 7 days
bun run .agents/skills/arc-search/cli/src/cli.ts search -q "react" --jobage 7 --format table

# Remote Python roles
bun run .agents/skills/arc-search/cli/src/cli.ts search -q "python" --format table

# Full details for a specific job
bun run .agents/skills/arc-search/cli/src/cli.ts detail ph3excboow --format plain
```

## Output formats

| Format | Best for |
|--------|----------|
| `json` | Default — programmatic use, passing IDs to `detail` |
| `table` | Quick human-readable scanning (includes a `[source]` tag per row) |
| `plain` | Reading a single job's full detail (`detail` command) |

All errors are written to **stderr** as `{ "error": "...", "code": "..." }` and the process exits with code `1`.

## Notes

- **Query is a technology/skill tag, not a job title search.** Arc organizes its board
  into one static page per tag (`flutter`, `react`, `android`, ...), not a full-text
  search engine. An unrecognized tag returns **zero results** — confirmed live that Arc
  itself silently redirects an unmatched slug to its own generic, unfiltered firehose of
  every remote job on the site, and this skill deliberately does not pass that through as
  if it matched your query.
- **Only page 1 is reachable.** Arc's category pages cap out around 30 results per tag
  even when more exist (`totalExternalJobCount` can be higher); no working pagination
  parameter was found after testing several candidates live. `--page 2` and beyond
  return an empty result set rather than silently repeating page 1.
- **No confirmed server-side date/recency parameter.** `--jobage` is implemented as a
  client-side filter over each result's own posted date, so it only filters *within*
  whatever page 1 returns.
- **Two result sources, one field to tell them apart.** `source: "arc"` is a listing
  applied through Arc's own platform (company name sometimes withheld until application);
  `source: "external"` is aggregated from elsewhere (e.g. LinkedIn) and always has a full
  detail page, including the `externalUrl` of the original posting.
- **`detail` on an `"arc"`-sourced job will fail** with a `DETAIL_UNAVAILABLE` error —
  every Arc-native listing tested redirected to the generic listing page instead of
  resolving, likely gated behind an account. `"external"`-sourced jobs always resolve.
- Job IDs are short lowercase alphanumeric strings (e.g. `ph3excboow`) — pass them as-is to `detail`.
