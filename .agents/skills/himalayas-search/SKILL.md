# Himalayas Search Skill

Search live job listings from Himalayas (himalayas.app), an international
remote-tech job board. No authentication, no API key, and **zero runtime
dependencies** — it runs with just `bun`.

> This skill was generated by `/add-portal`. Like `weworkremotely-search` and
> `arc-search`, this is a global board — useful for the international remote-USD
> roles this candidate's Location Filter marks acceptable, not a Brazil-market
> portal.

## Why this skill uses RSS, not HTML

Every ordinary page on this site (the `/jobs` search page, individual job pages)
returned an **HTTP 403 Cloudflare managed challenge** ("Just a moment...") for this
CLI's honest, non-browser User-Agent — confirmed live, and confirmed to persist even
with a full browser User-Agent string (a genuine JS/TLS challenge, not a UA-string
check). The feed URL itself was discovered from the plain, unblocked `/rss` info
page, which points at `himalayas.app/jobs/rss` — that endpoint returned real content
with the same honest UA every other page rejected. This skill does not attempt to
spoof its way past the challenge (that escalation path belongs to
`.claude/skills/job-application-assistant/09-web-research.md`'s robots.txt gate, not
a portal CLI's default) — it simply uses the feed, a legitimate, publicly-linked data
source in its own right, as its only data source.

Two consequences follow from this:
1. **No server-side keyword search.** The feed has none — confirmed by testing
   `?searchQuery=`, `?q=`, `?category=`, and `?limit=`, all of which returned the
   identical 20 items as no params at all. `--query` is a client-side filter.
2. **No separate detail-page fetch.** The feed already embeds each job's full
   description (`<content:encoded>`), so `detail` re-reads the same feed rather than
   fetching a second page.

## When to use this skill

- Search for remote developer/engineering jobs globally by keyword
- Filter by how recently a job was posted (using the feed's real publish date)
- Narrow by country restriction (most listings have none — worldwide-eligible)
- Get a job's full description, including compensation when disclosed, and its
  application deadline, without an extra network round-trip

## Commands

### Search job listings

```bash
bun run .agents/skills/himalayas-search/cli/src/cli.ts search --query "<keyword>" [flags]
```

Key flags:
- `--query <text>` / `-q <text>` — **required.** Split into words and matched (AND, case-insensitive) against each listing's company, title, categories, and description text, e.g. `"flutter"` or `"mobile engineer"`.
- `--location <text>` / `-l <text>` — optional. Client-side substring filter over the feed's own country-restriction list, e.g. `"United States"`. Most listings have no restriction at all and are excluded by this filter, not vacuously matched.
- `--jobage <days>` — only postings within N days, using each item's real publish date.
- `--limit <n>` / `-n <n>` — cap total results emitted (client-side).
- `--format json|table|plain` — default `json`.

No `--page` flag — see Notes.

### Fetch full job detail

```bash
bun run .agents/skills/himalayas-search/cli/src/cli.ts detail <id|url> [--format json|plain]
```

`id` is the `<company-slug>/<job-slug>` composite from a `search` result's `id`
field (e.g. `featherless-ai/founding-sales-engineer`). You may also pass a full
`himalayas.app/companies/<company-slug>/jobs/<job-slug>` URL. Re-reads the feed and
looks up the job by that composite — only finds a posting still present in the
feed's rolling 20-item window (see Notes).

## Usage examples

```bash
# Flutter-mentioning roles (matched via description, not just title)
bun run .agents/skills/himalayas-search/cli/src/cli.ts search -q "flutter" --format table

# Mobile engineering roles posted in the last 7 days
bun run .agents/skills/himalayas-search/cli/src/cli.ts search -q "mobile engineer" --jobage 7 --format table

# US-restricted engineering roles only
bun run .agents/skills/himalayas-search/cli/src/cli.ts search -q "engineer" -l "United States" --format table

# Full detail for one job
bun run .agents/skills/himalayas-search/cli/src/cli.ts detail featherless-ai/founding-sales-engineer --format plain
```

## Output formats

| Format | Best for |
|--------|----------|
| `json` | Default — programmatic use, passing ids to `detail` |
| `table` | Quick human-readable scanning (the id column is never truncated — a cut id silently becomes a different, wrong id) |
| `plain` | Reading a single job's full detail (`detail` command), or a scan of search results with categories visible |

All errors are written to **stderr** as `{ "error": "...", "code": "..." }` and the process exits with code `1`.

## Notes

- **No server-side search parameter exists.** `searchQuery=`, `q=`, and `category=`
  were tested live and confirmed to be no-ops (the feed returns the same 20 items
  regardless) — `--query` is purely client-side, matched by word (AND) against
  company, title, categories, and description text.
- **Hard 20-item cap, no pagination.** The feed always returns exactly the latest 20
  postings site-wide, refreshed continuously — this is a firehose, not a stable
  archive. A niche technical query can legitimately return 0 client-side matches
  simply because none of the current 20 happen to fit; that is not a broken search.
  Passing `--page` is rejected (`UNKNOWN_FLAG`) rather than silently accepted and
  ignored.
- Every result carries one bonus field beyond the base contract: `deadline`
  (Himalayas' own `expiryDate`, when the posting states one) — the sister
  `weworkremotely-search` skill's equivalent field exists in its feed's schema but is
  empty on every item observed there, so this is a genuine advantage of this portal.
- `--location` reflects an **explicit** restriction list; its absence means
  worldwide-eligible, not "unknown" — the skill keeps these two facts distinct rather
  than treating a missing restriction as a filter match.
- `detail` only finds a job still present in the feed's rolling window. An older
  posting that has scrolled out returns `NOT_FOUND` — this does not mean the posting
  is gone from the live site, only that this skill's one data source (the feed) no
  longer carries it.
- Himalayas may rate-limit; the CLI retries 429/5xx with exponential backoff. Keep
  request volume low regardless — this is a Cloudflare-fronted site.
